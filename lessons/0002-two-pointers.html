Pattern 1: Two Pointers

First pattern in the rebuild. You've almost certainly used this before without naming it — the goal here isn't to learn it from scratch, it's to get fast at recognizing when it applies and writing it clean under time pressure.

Why this one first

Two pointers is the highest-yield starting pattern: it's simple enough to fully internalize in one session, it directly sets up sliding window (lesson 3), and it shows up constantly in easy/medium interview problems. If pattern recognition is what's rusty — not the underlying logic — this is where that comes back fastest.

Recognize it

Reach for two pointers when you see:

  • A sorted array or string (or one you can sort without losing needed info).
  • You're looking for a pair or triplet that satisfies some condition against a target.
  • A palindrome or symmetry check.
  • You need to merge two sorted sequences, or process in place under a size constraint.
  • A brute-force nested loop gets you O(n²), and the data has enough structure (sorted, in-place) to do better.
Recall — no peeking
Without scrolling up: what's the time complexity two pointers gets you, versus the nested-loop brute force it replaces? Say both numbers out loud.

The two variants

Opposite ends, converging. One pointer starts at index 0, the other at len-1. Each step, you use the relationship between the two values to decide which pointer moves. Classic case: Two Sum on a sorted array.

Same direction, slow/fast. Both pointers start near the beginning and move forward. The fast pointer explores; the slow pointer marks a boundary — "everything before me is already correct." Classic case: removing duplicates from a sorted array in place. 

// Opposite-ends — e.g. Two Sum II (input already sorted ascending)
func twoSum(nums []int, target int) []int {
    lo, hi := 0, len(nums)-1
    for lo < hi {
        sum := nums[lo] + nums[hi]
        switch {
        case sum == target:
            return []int{lo, hi}
        case sum < target:
            lo++
        default:
            hi--
        }
    }
    return nil
}
In the opposite-ends template above, if sum < target, why do we move lo forward rather than hi backward? 
// Same-direction — e.g. remove duplicates from sorted array, in place
func removeDuplicates(nums []int) int {
    slow := 0
    for fast := 1; fast < len(nums); fast++ {
        if nums[fast] != nums[slow] {
            slow++
            nums[slow] = nums[fast]
        }
    }
    return slow + 1
}
In the same-direction template, what does slow represent at any point mid-loop?
Interview-day reminder
Per lesson 1: solving it isn't the bar anymore, narrating it is. Say the recognition signal out loud before you write a line — "this is sorted and I need a pair, so opposite-ends two pointers" — then code it.
Practice — 15 minutes, out loud

Pick one, set a 15-minute timer, and narrate your approach before and while you code it in Go:

  • Easy: Valid Palindrome — opposite-ends variant.
  • Medium: Container With Most Water — opposite-ends, with a greedy-move justification you should be able to defend out loud.

If you finish early, try 3Sum — same-direction fixed pointer plus an opposite-ends inner loop, the natural next step up.
